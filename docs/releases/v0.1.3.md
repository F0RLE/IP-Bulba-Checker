# Bulbascan v0.1.3

## Summary

`v0.1.3` turns Bulbascan into a practical selective-proxy classifier with stronger dual-vantage decisions, cleaner operator outputs, broader service coverage, and modern router export formats.

This release is centered on one product goal:

- produce more reliable `DirectOk` vs `ProxyRequired` vs `ManualReview` decisions
- reduce publication noise
- make the resulting artifacts easier to consume in real routing workflows

## Major Changes

### Accuracy and classification

- Added DNS-level block detection:
  - system DNS vs DoH comparison
  - resolver health and mismatch confirmation
  - stronger poisoned-answer evidence

- Tightened dual-vantage confidence rules:
  - cleaner `ConfirmedProxyRequired` vs `CandidateProxyRequired`
  - weaker transport noise no longer escalates as aggressively
  - local/control ambiguity is reported more explicitly

- Improved browser-assisted confirmation:
  - challenge-page labeling for Cloudflare and AWS WAF challenge/captcha responses
  - bounded browser budget for bulk scans
  - challenge-family reuse to avoid repeated browser verification

- Expanded service-profile coverage:
  - wider AI, fintech, streaming, social, and Russian service coverage
  - better multi-role host support
  - more useful login, browser, API, and console entrypoints

### Reports and publication workflow

- Added stronger operator-facing reports:
  - `txt/comparison.txt`
  - `txt/service-geo.txt`
  - `txt/validation.txt`
  - `txt/publication.txt`
  - `txt/hotspots.txt`

- Added publication guidance:
  - strict publishable domains
  - review-only domains
  - direct domains
  - hot / warm / cold rescan queues

- Added incremental publication workflow:
  - publish tiers
  - queue persistence in state
  - operator-facing publication summaries

### Export formats and output cleanup

- Added direct `sing-box` binary rule-set generation:
  - `.srs` output when local `sing-box` is available

- Added Mihomo / Clash.Meta support:
  - text rule sets and providers by default
  - `.mrs` output when local compiler is available

- Simplified result layout:
  - outputs grouped by format:
    - `txt/`
    - `json/`
    - `yaml/`
    - `bin/`
  - shorter output names
  - smaller default `router` surface

- Moved worker state out of the project root.
- Nested default persistent state under `results_dir/state`.

### Tooling and runtime

- Added `bulbascan.toml` global configuration support:
  - auto-load from working directory
  - explicit `--config`
  - `--no-config`
  - sane precedence rules

- Improved cross-platform runtime behavior:
  - broader browser auto-detection
  - plain-text progress fallback when ANSI is unavailable
  - more predictable browser-assisted behavior on Windows, macOS, and Linux

- Extended CI coverage:
  - checks now cover `nightly` and `dev`
  - branch workflow and shared agent process were documented

## Operator Impact

`v0.1.3` is the first version where Bulbascan is clearly usable as:

- a country-level selective-proxy classifier
- a router/export artifact generator
- a review-oriented operator tool instead of just a raw scan engine

The main practical improvements are:

- fewer false-positive escalations
- better publication separation between strict and review outputs
- cleaner result bundles
- broader modern routing format support

## Upgrade Notes

- Output paths changed:
  - reports and lists are now grouped into format-specific subdirectories

- Default persistent state behavior changed:
  - if `--state-dir` is not provided, state now lives under `results_dir/state`

- Worker count state no longer writes `.bulbascan_workers` into the repository root.

- Policy and governance documents now live under `docs/project/`.

## Follow-up

The next roadmap cycle (`v0.1.4`) focuses on productization rather than more transport research:

- reducing output surface
- defining clearer presets
- cleaning up state lifecycle
- adding repeatable benchmarking and release validation
- preparing distributable feed bundles
