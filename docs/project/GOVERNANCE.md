# Governance

Bulbascan uses a simple owner-led governance model.

## Roles

### Owner

The project owner is the final decision-maker for:

- repository control
- roadmap direction
- merge policy
- release policy
- branding
- commercial licensing and OEM agreements

The owner may delegate technical work, but ownership of the project and its commercial direction remains centralized.

### Maintainers

Maintainers are trusted contributors who help keep the project moving.

They may:

- review pull requests
- propose and refine roadmap work
- help maintain code quality and CI health
- prepare feature branches and implementation work

Maintainers do not automatically receive ownership, trademark control, or commercial licensing authority.

### Contributors

Contributors may:

- open issues
- propose fixes and features
- submit pull requests
- improve documentation, tests, signatures, and service profiles

Contributors help shape the codebase, but project direction, releases, and commercial licensing remain owner-controlled.

## Project model

Bulbascan is developed as:

- a public community project under [AGPL-3.0](../../LICENSE)
- a commercially licensable product under separate terms described in [COMMERCIAL-LICENSE.md](COMMERCIAL-LICENSE.md)

This means:

- community use and contributions are welcome
- technical collaboration can involve multiple maintainers and contributors
- commercial/OEM licensing decisions stay with the owner

## Contribution and licensing boundary

Unless explicitly agreed otherwise in writing:

- pull requests are made to the public AGPL-licensed repository
- accepted contributions may be used in the project's dual-licensing model
- project ownership is not transferred by contributing

## Practical rule

Bulbascan can have many contributors and multiple maintainers, but a single owner-controlled commercial path.
