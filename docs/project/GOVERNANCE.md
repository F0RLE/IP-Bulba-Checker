# Governance

## Maintenance Status

Bulbascan is currently in a temporary maintenance pause.

The main blocker is not basic code scaffolding anymore, but the difficulty of making a country-block scanner accurate enough for production selective-proxy decisions while being maintained by a solo developer. Until that changes, the repository should be treated as paused rather than actively developed.

Bulbascan uses a simple owner-led governance model.

## Roles

### Owner

The project owner is the final decision-maker for:

- repository control
- merge policy
- release policy
- branding

The owner may delegate technical work, but ownership of the project remains centralized.

### Maintainers

Maintainers are trusted contributors who help keep the project moving.

They may:

- review pull requests
- help maintain code quality and CI health
- prepare feature branches and implementation work

Maintainers do not automatically receive ownership or trademark control.

### Contributors

Contributors may:

- open issues
- propose fixes and features
- submit pull requests
- improve documentation, tests, signatures, and service profiles

Contributors help shape the codebase, but project direction and releases remain owner-controlled.

## Project model

Bulbascan is developed as a public community project under the [MIT License](../../LICENSE).

This means:

- community use and contributions are welcome
- technical collaboration can involve multiple maintainers and contributors

## Contribution and licensing boundary

Unless explicitly agreed otherwise in writing:

- pull requests are made to the public MIT-licensed repository
- accepted contributions remain part of the MIT-licensed project
- project ownership is not transferred by contributing

## Practical rule

Bulbascan can have many contributors and multiple maintainers, while project ownership remains centralized.
